# Predicting Student Exam Scores

**Mission:** help schools and tutors decide where to spend limited support hours. Given a student's study habits, attendance, home support and access to resources, the model estimates the exam score that student is heading for, so that at-risk students can be identified before the exam rather than after it.

This is a regression problem on real student data — deliberately **not** house-price prediction.

## Dataset

**Student Performance Factors** — 6,607 students × 20 columns, one row per student.

- **Source:** [Kaggle — Student Performance Factors](https://www.kaggle.com/datasets/lainguyn123/student-performance-factors)
- **Local copy:** `summative/data/StudentPerformanceFactors.csv`
- **Target:** `Exam_Score` (continuous, roughly 55–100)

The variables span several dimensions, which is what makes it rich enough for a multivariate fit:

| Group | Columns |
|---|---|
| Study behaviour | `Hours_Studied`, `Attendance`, `Previous_Scores`, `Tutoring_Sessions` |
| Home support | `Parental_Involvement`, `Parental_Education_Level`, `Family_Income`, `Distance_from_Home` |
| School / social | `Teacher_Quality`, `Peer_Influence`, `Access_to_Resources`, `Extracurricular_Activities` |
| Personal | `Motivation_Level`, `Internet_Access`, `Learning_Disabilities` |
| Dropped | `Sleep_Hours`, `Physical_Activity`, `Gender`, `School_Type` |

The four dropped columns showed near-zero correlation with `Exam_Score` in the heatmap and boxplots, so they were removed during feature engineering.

## Results

All six models share the same standardized 80/20 split. The winner is the model with the **lowest test RMSE**.

| Model | RMSE | MAE | R² |
|---|---|---|---|
| **Ridge Regression (deployed)** | **1.808** | 0.493 | 0.769 |
| Gradient Descent (custom) | 1.808 | 0.493 | 0.769 |
| OLS LinearRegression | 1.808 | 0.493 | 0.769 |
| Stochastic LR (SGDRegressor) | 1.816 | 0.491 | 0.767 |
| Random Forest | 2.094 | 1.044 | 0.690 |
| Decision Tree | 2.550 | 1.613 | 0.540 |

The tree and the ensemble both lose to every linear model, which confirms the relationship really is close to linear — so the regularized linear model is what gets saved to `summative/linear_regression/models/best_model_pipeline.joblib` and served by the API.

## Public API

- **Base URL:** https://regression-analysis-mobile-application-vs8p.onrender.com
- **Swagger UI:** https://regression-analysis-mobile-application-vs8p.onrender.com/docs
- **Youtube video:**https://youtu.be/suXja6yLZ64
- **Prediction endpoint:** `POST /predict`

Example:

```bash
curl -X POST https://regression-analysis-mobile-application-vs8p.onrender.com/predict \
  -H 'Content-Type: application/json' \
  -d '{"Hours_Studied":22,"Attendance":90,"Previous_Scores":80,"Tutoring_Sessions":2,
       "Parental_Involvement":"High","Access_to_Resources":"Medium","Motivation_Level":"High",
       "Family_Income":"Medium","Teacher_Quality":"High","Peer_Influence":"Positive",
       "Parental_Education_Level":"College","Distance_from_Home":"Near",
       "Extracurricular_Activities":"Yes","Internet_Access":"Yes","Learning_Disabilities":"No"}'
```

Every field is range- and type-constrained with Pydantic, so out-of-range values come back as a 422 rather than a nonsense score. `POST /retrain` and `POST /retrain/csv` refit the pipeline on new labelled data and hot-swap the served model.

CORS is configured with an explicit origin list, explicit methods (`GET`, `POST`, `OPTIONS`), explicit headers (`Accept`, `Authorization`, `Content-Type`) and credentials enabled — no wildcards.

## Running it

### Task 1 — notebook

```bash
pip install -r requirements.txt
jupyter notebook summative/linear_regression/multivariate.ipynb
```

Make a one-off prediction from the saved model:

```bash
python summative/API/prediction.py --hours 22 --attendance 90 --previous 80
```

### Task 2 — API

```bash
uvicorn summative.API.main:app --reload --host 0.0.0.0 --port 8000
```

Docs at http://127.0.0.1:8000/docs

### Task 3 — Flutter app

```bash
cd summative/flutterApp
flutter pub get
flutter run
```

For the web build, use one of the allowed CORS ports:

```bash
flutter run -d chrome --web-port=5000
```

The app has one page: a text field for each of the 15 model inputs, a **Predict** button, and a display area that shows either the predicted exam score or an error when a value is missing or out of range.
